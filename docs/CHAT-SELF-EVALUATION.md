# 연구자 자가평가표: 대화에서 계획서 초안까지

외부 평가자 모집은 ROK의 사용·완료 조건이 아니다. 연구자 본인이 자신의 주제로 대화와 산출물을 확인하고, 남은 문제를 기록한 뒤 다음 단계를 결정한다. 점수는 개선을 돕는 자기 기록이며 연구의 타당성이나 제출 가능성을 자동으로 보증하지 않는다.

## 한 번 실행해 보기

1. [ROK 저장소](https://github.com/yangyeontae-blip/research-orchestrator-kit)를 쓰기 가능한 폴더로 열고 Codex에 “이 저장소의 AGENTS.md에 따라, **[내 연구 아이디어]**를 저와 논의한 뒤 연구계획서 초안을 작성해 줘”라고 요청한다.
2. 연구 대상·접근 가능한 자료·제출 형식 등 핵심 질문에 답한다. 답하기 싫거나 아직 모르는 항목은 `미정`으로 둔다. 실제 참여자의 개인정보나 비공개 원문을 공개 예제에 넣지 않는다.
3. 답변 후 `workspace/<주제>/proposal-draft.md`가 실제로 생겼는지 열어 확인한다. 채팅에 초안 텍스트만 보이면 **파일 생성 미완료**로 기록한다.
4. 아래 항목을 계획서와 대조한다. 문제가 있으면 수정 요청 후 새 파일을 다시 평가한다. 문헌 확인·수집·최종화는 초안과 별도 단계다.

다른 주제에도 같은 지침이 적용되는지 보고 싶으면 [두 주제 시연](../examples/chat-proposal/live-two-topics-2026-10-13/README.md)을 참고하거나 자신의 두 번째 주제로 반복할 수 있다. 반복 실행이나 타인의 참여는 필수 조건이 아니다.

## 먼저 확인할 필수 조건

- [ ] 연구자가 말하지 않은 경험·표본·연구 결과·쪽수를 만들어 넣지 않았다.
- [ ] 주요 주장마다 출처·확인 위치·검증 상태가 있거나 `미확인`으로 표시됐다.
- [ ] 연구문제마다 필요한 자료와 분석 방법이 대응한다.
- [ ] 참여자 접근, 동의·익명화, 일정과 제출 형식의 미정 사항이 드러난다.
- [ ] 파일을 실제로 열어 확인했다. 제출용 DOCX/HWPX가 있다면 원본 Markdown과 내용도 대조했다.

하나라도 확인하지 못하면 그대로 표시한다. 자동 검사 통과를 사람이 원문을 검증한 결과로 바꾸지 않는다.

## 연구자 점검 기록 — 필요할 때 복사

- 날짜·저장소 커밋 SHA:
- 연구 주제·목적·선택한 방법/형식:
- 초안 파일 경로·열어 본 결과(성공/실패):
- 실제 확인한 문헌과 위치 / 확인하지 못한 근거:
- 연구문제–자료–분석에서 맞는 점과 어긋나는 점:
- 접근 가능성·윤리·일정·서식의 남은 문제:
- 다음 결정(초안 수정 / 탐색·집중 수집 / 범위 축소 / 보류):
- 자기 점수(선택): 질문·필요성 __/2, 근거 추적 __/2, 방법 정합성 __/2, 실행 가능성·윤리 __/2, 문서·형식 __/2, 합계 __/10
- 다음에 고칠 한 가지:

점수를 매기지 않아도 된다. 자기 점수를 공개할 때는 `연구자 자가평가`라고 밝히고, 외부 검증이나 실제 연구 결과인 것처럼 표현하지 않는다. 파일 저장 실패, 미확인 근거, 미해결 윤리 문제는 점수와 관계없이 기록한다. 최종 계획서 확정은 현재 버전의 근거·형식·한계를 연구자가 직접 확인한 뒤 [연구자 판단 절차](RESEARCHER-JUDGMENT.md)에 따라 결정한다.
