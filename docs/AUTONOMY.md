# 자율성 정책

ROK의 자율성은 "무엇이든 알아서 한다"가 아니라 **한 번 승인한 범위 안에서 멈추지 않고 끝까지 실행하되, 정해진 조건에서는 반드시 멈추는 것**입니다. 이 문서는 그 범위와 멈춤 조건, 모호한 근거를 다루는 규칙, 한계를 정리합니다. 구현 위치는 [AGENT-DESIGN.md](AGENT-DESIGN.md)를 보세요.

## 1. 자율 수행 범위 (`rok authorize` 승인 후 `rok run`)

승인 한 번에 아래가 묶입니다(`authorizeRun`, `src/execution.mjs`).

| 승인에 포함되는 것 | 내용 |
|---|---|
| 제공자 | `codex_cli` 또는 `claude_cli`만 허용. 유료 API로 자동 전환 없음 |
| 입력 목록 | 명시한 텍스트 파일(md·txt·json)과 SHA-256. 목록 밖 파일은 `New input needs scope approval`로 거부 |
| 검색어 | 익명화된 검색어 목록. 민감정보가 있으면 거부 |
| 상한 | 후보 50, 내려받기 15, 동시성 ≤ 2, 보완 수집 2회, 워커 호출 12회, **API 예산 0** |

승인 뒤 자율로 하는 일: 문헌 검색·공개 원문 내려받기·제목 일치 확인·파싱, 역할별 워커 호출, 스키마 검증, 인용 위치 대조, 품질 보고서와 DOCX 생성, 블루프린트 추출. 사람이 중간에 개입하지 않아도 이어집니다.

## 2. 반드시 멈추는 조건

| 조건 | 멈춤 방식 | 근거 코드 |
|---|---|---|
| 대기 작업 없음 = 사람의 결정이 필요한 관문 | `status: waiting` | `runWorkflow`의 `if(!next)` |
| 호출 상한(`worker_calls`) 소진 | `limit_reached` | 루프 조건 |
| 사용자가 `rok stop` | `stopped`, 진행 중 호출은 AbortController로 중단 | `stopRun`, `stop.json` |
| 워커가 `partial`/`failed` 반환 | 그 사유로 즉시 반환, 산출물 보존 | 영수증 처리 |
| 범위 밖 입력·500 KB 초과·민감정보 | 예외, 작업은 `partial`로 기록 | 입력 통제 |
| 매칭된 원문이 하나도 없음 | `partial`, 원문 업로드 또는 검색 범위 수정 안내 | literature 분기 |
| 사용량·요금 한도 | 한도 메시지로 정리 후 중단, **유료 대체 없음**, `rok resume`으로 이어감 | `workerFailure` |
| 승인 해시와 현재 산출물 불일치 | 승인 무효, 새 승인 필요 | `engine.mjs` |
| 초안이 초안 기준 검사 미통과 | 수집 관문 전에 정지(`rework`로 되돌림) | `quality.mjs` |
| 영상 렌더가 필요함 | `local_tool_required`로 넘김(모델 호출 없음) | `video_render` 분기 |

사람 관문은 5개입니다: 범위 승인 → 수집 승인 → 보완 항목 승인 → 사용 검증 → `finalize`. 승인·사용 검증·`rework`는 대화형 터미널에서 직접 입력해야 하며, 에이전트의 비대화형 셸에서는 거부됩니다.

## 3. 모호하거나 상충하는 근거를 다루는 규칙

모델이 근거를 찾지 못했다고 해서 멈추거나 지어내지 않습니다. 단계별로 다르게 지시합니다(`STAGE_RULES`).

- **검토자(review):** 근거 공백·반증·확인 불가 주장은 R1, R2… 번호 붙은 **발견 사항**으로 적고 검토는 `completed`로 마칩니다. 검토 자체를 못 한 경우에만 `partial`/`failed`.
- **작성자(plan/revise):** 근거가 없는 주장은 삭제하지 않고 본문에 **"미검증"으로 표시**합니다.
- **하네스:** 인용이 해당 쪽에 없으면 `location_check: failed`로 기록하고 근거에서 제외합니다. 같은 인용이 정확히 한 다른 쪽에만 있으면 쪽 번호만 교정하고(`correctPages`), 여러 쪽에 있으면 교정하지 않습니다.
- **상충(`relation: contradiction`)** 은 별도 관계로 장부에 남아 보완 승인 때 연구자에게 보입니다.
- 증거 상태는 4단계로만 표시합니다: `original_verified`, `parsed_verified`, `metadata_only`, `unverified`.

## 4. 실패와 재개

- 모든 작업은 claim 리스를 가지며, 잠금에는 PID와 호스트가 기록됩니다. 죽은 프로세스의 잠금은 `resume` 때 회수됩니다.
- 중단된 워커는 `partial`로 닫히고 저장된 출력은 보존됩니다. `rok resume`은 실패한 작업만 다시 시작합니다.
- 입력이 바뀐 상태로 돌아온 영수증도 받되 `binding_warning`을 남깁니다. `retry --rebind`는 자유 입력만 다시 묶고 **승인에 묶인 계획서·보고서는 다시 묶지 않습니다.**

## 5. 한계 (정직한 경계)

1. **로컬 사용자는 신뢰 경계입니다.** 승인 관문은 CLI에서 대화형 입력을 요구하지만, 같은 계정의 사용자가 엔진 API를 직접 호출하면 우회할 수 있습니다. 채팅 브리지는 호스트가 실제 사용자 응답만 전달한다고 가정합니다(`trust: local-host; not independent proof of human identity`).
2. **공유 모델 편향.** 작성과 검토는 별도 세션이지만 같은 모델 계열일 수 있어, 검토자가 작성자와 같은 오류를 놓칠 수 있습니다. 그래서 의미 판단은 근거로 세지 않고 위치 대조만 근거로 셉니다.
3. **의미 검증 없음.** 인용문이 쪽에 있다는 것은 확인하지만, 그 인용이 주장을 정말 뒷받침하는지는 자동으로 판단하지 않습니다(`semantic_verified: false`). 연구자가 원문과 대조합니다.
4. **스캔본·OCR 없음.** 글자가 없는 PDF는 근거가 되지 못합니다.
5. **한 작업 폴더당 하나의 흐름**을 가정합니다. 분산 파일시스템 동시성은 검증하지 않았습니다.
6. **합성 데이터 중심 검증.** 정량 평가는 결함 주입 실험이며(EVALUATION.md), 실제 연구자 대상 사용성 검증은 하지 않았습니다.
