# 연구자의 판단

ROK에서 계획서가 "완료"되었는지를 정하는 사람은 연구자 한 명뿐입니다. 외부 평가 점수, 자동 품질 점수, AI 검토 의견은 판단을 돕는 기록일 뿐 완료를 대신 선언하지 않습니다.

## 무엇을 자동으로 하고, 무엇을 연구자가 정하는가

| 자동으로 하는 일 | 연구자가 정하는 일 |
|---|---|
| 승인된 범위 안에서 검색·원문 확보·파싱·문서 변환·재시도 | 연구문제와 연구방법, 그 변경 |
| 계획서·검토 보고서·블루프린트 초안 작성 (Codex·Claude) | 외부 도구로 보낼 자료와 검색 범위, 작업량 상한 |
| 파일 해시 결속, 인용 위치·쪽수 자동 대조 | 근거가 주장을 실제로 뒷받침하는지 |
| 형식·대응표·인용–참고문헌 자동 검사 | 연구문제–자료–분석의 의미상 정합성 |
| 실패·중단 기록과 재개 | 보완수집을 더 할지, 범위를 줄일지, 한계로 남길지 |
| 변경된 절과 이전 승인의 무효화 표시 | 보완본 채택과 최종본 확정 (`finalize`) |

## 판단 지점

실행은 다음 순간에만 멈추고 연구자에게 묻습니다.

1. **실행 범위 승인** — 목적·형식·마감, 입력 파일과 해시, 검색어, 실행 도구, 상한(후보 50건·원문 15건·보완 2회·유료 API 0원)을 한 번에 확인합니다.
2. **계획서 실사용 확인** — 작성 담당과 다른 확인자가 핵심 근거와 연구문제–자료–분석 대응을 직접 확인합니다.
3. **수집 승인** — 정확한 계획서 해시에 대해 문헌 수집을 허락합니다. 계획서가 바뀌면 다시 묻습니다.
4. **반영 승인** — 검토 보고서의 수정 제안 중 반영할 항목을 고릅니다. 모두 반려할 수도 있습니다.
5. **보완수집 여부** — 두 차례 보완 뒤에도 핵심 근거가 없으면, 반복 검색 대신 범위 축소·질문 변경·한계 명시 중에서 고릅니다.
6. **최종 확정 (`finalize`)** — 아래 기록이 모두 현재 버전과 일치할 때만 가능합니다. 이후 파일이 바뀌면 확정은 자동으로 무효가 되고, `reopen`으로 다시 엽니다.

## 최종 확정에 필요한 기록

- 검토를 거쳐 승인된 항목만 반영한 보완본
- 현재 계획서 해시에 묶인 근거·방법·인용 자동 검사 결과
- 계획서 실사용 확인 기록
- 내보낸 DOCX 또는 HWPX를 열어 Markdown 원본과 대조한 기록
- 남은 한계와 미확인 근거에 대한 연구자의 기술

## 하지 않는 일

- 외부 평가자 점수나 "몇 점 달성" 같은 지표로 완료를 선언하지 않습니다.
- 자동 점수가 높다는 이유로 관문을 통과시키지 않습니다.
- 사람이 확인하지 않은 항목을 확인했다고 기록하지 않습니다.
- 읽지 않은 문헌, 만들어진 쪽수, 실제로 하지 않은 경험을 근거로 쓰지 않습니다.
